## Conflicts

### 1. Working tree — hard gate on every unit

- Two independent bodies of uncommitted work share the tree: the contract-test restructure
  (8 git-tracked renames, `docs/atdd/test-taxonomy.md`, `component-tests.yaml`,
  `plans/20260812-1600` path reference) and the user's `20260812-1600` implementation
  (`build.gradle`, `component-tests.yaml`, `ErpRealParityContractTest.java`, the commit-stage
  workflow).
- **Overlap:** `component-tests.yaml` is edited by both. The restructure changed the
  `provider-verification` glob to `contract.internal.*`; the ERP work added the
  `external-contract-real` suite. Both edits are in the file now and neither is committed.
- **Why hard:** no unit below can start against a tree where two changes are already interleaved —
  any new edit compounds the entanglement, and a partial revert becomes impossible to do cleanly.
- **Recommended resolution:** land U1 first as **two commits** (restructure, then ERP work),
  splitting `component-tests.yaml` by hunk. Everything else waits.

### 2. `ErpRealParityContractTest.java`, `build.gradle`, `component-tests.yaml` — coordination conflict

- `20260812-1600` (implemented, uncommitted) created the `erpSimulatorImage` task, the
  `myshop/erp-simulator:contract-test` tag, and the singleton container inside
  `ErpRealParityContractTest`.
- `20260814-1610` items 4 + 5 **restructure exactly those**: extract the container to a shared
  holder, rename the task to `externalSimulatorImage`, retag the image.
- **Why coordination, not hard:** the second change is a clean refactor of the first, but only if
  the first is committed. Running them against one dirty tree means the rename lands as an
  unreviewable part of the original diff.
- **Recommended resolution:** strict serialisation — U1 lands, then U5. Do not approve
  `20260814-1610` for execution before `20260812-1600` is committed.

### 3. `ErpDsl.java` / `TaxDsl.java` — soft conflict with a referenced-only plan

  what currently justifies the `String`-typed price/rate parameters: *"Prices and discounts are
